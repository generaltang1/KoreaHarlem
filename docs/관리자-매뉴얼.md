# KoreaHarlem 관리자(운영자) 테스트 매뉴얼

프로덕션: https://korea-harlem.vercel.app  
로컬: http://localhost:3000  

이 문서는 **관리자 역할**로 상품 등록 → 주문·배송 → CS 최종 처리까지 테스트할 때 사용합니다.  
구매자 절차는 `docs/구매자-매뉴얼.md`를 함께 보세요.

---

## 0) 관리자 접속

1. 관리자 권한이 있는 계정으로 `/login`
2. `/admin` 대시보드  
   - 아티스트 · 음악 · **상품 관리** · **주문 관리** · 이벤트

> `profiles.role = admin` 인 사용자만 Admin 접근 가능합니다.

---

## 1) 상품 등록 · 수정

### 경로
- 목록: `/admin/products`
- 등록: `/admin/products/new`
- 수정: `/admin/products/[id]/edit`

### 등록 체크리스트

| 항목 | 권장 |
|------|------|
| 제목·가격·이미지 | 필수 · 이미지 중복/깨짐 없게 |
| **In Store 카테고리** | Merch / CD / Ticket 필수 · Merch면 Tops·Bottoms·Accessory |
| **진열상태** | 진열함 → 공개 노출 |
| **판매상태** | 판매함 → 구매 가능 / 판매안함 → 노출만(티켓·프리오더용) |
| **사이즈·재고** | 사이즈별 재고 · 총재고는 동기화됨 |
| 배송비·무료배송 기준 | 필요 시 |

### 재고 수정 (재입고)
1. 상품 수정 화면 **수기 재고 조정** (StockAdjust)
2. 수량·사유 입력 후 반영
3. `products.stock`이 갱신되면 메인·In Store에 **다시 노출** (품절 숨김 해제)

### 공개 노출 규칙 (기억)
| 조건 | 메인·In Store 목록 |
|------|-------------------|
| 진열안함 | 안 보임 |
| 재고 0 (품절) | 안 보임 |
| 판매안함 + 진열함 + 재고 있음 | 보임 · 구매 불가 |

정렬: **최신 등록순**

## 2) 구매 유도 · 결제 확인

1. 구매자 매뉴얼대로 회원/비회원 결제 진행
2. `/admin/orders`에서 주문 목록 확인
3. 주문 상세 `/admin/orders/[id]`  
   - 주문자 · 배송지 · 결제 · 품목 · 타임라인

### 결제대기 주문
- 결제 미완료면 Admin에서 **취소**(재고 복구, 토스 환불 없음)

---

## 3) 배송 처리

### 경로
`/admin/orders` · `/admin/orders/[id]` · (목록에서 일괄 상태 변경 가능)

### 권장 흐름
```
결제완료(paid) → 배송준비중(preparing) → 배송중(shipped) → 배송완료(delivered)
```

| 단계 | 할 일 |
|------|--------|
| 배송준비중 | 포장 준비 |
| 배송중 | **택배사 · 송장번호** 입력 |
| 배송완료 | 수령 확인 |

> **CS(반품/교환/환불) 요청은 배송중·배송완료에서만** 고객이 할 수 있습니다.  
> CS 테스트를 하려면 반드시 shipped 또는 delivered까지 진행하세요.

---

## 4) 회원 배송 전 취소 · 직접 환불

### 고객(회원) 셀프 취소
- paid / preparing → 고객이 마이페이지에서 취소 가능 (토스 환불)

### Admin 직접 환불
주문 상세 하단 **취소 / 환불**
- 토스 환불 실행 (전액·부분)
- 재고 복구 옵션

> CS와 **별도** 경로입니다. CS 없이 환불할 때 사용.

---

## 5) CS 처리 (반품 · 교환 · 환불) — 최종 단계

### 위치
`/admin/orders/[id]` → **CS 요청 (반품/교환/환불)** 패널  
회원·비회원 요청 **동일 UI**

### 버튼

| 버튼 | 언제 | 동작 |
|------|------|------|
| **승인** | 요청접수 | 수락. **교환**이면 희망 사이즈 재고 hold |
| **반려** | 요청/승인 | 거절 · 주문 상태 복구 · hold 해제 |
| **회수·검수 완료** | 반품·교환 | 물품 확인 완료 |
| **처리 완료** | 요청~검수 | 실제 환불·교환 마무리 |

하단 옵션 (반품·환불 open 시):
- ☑ 처리 완료 시 **토스 환불** 실행
- ☑ 처리 완료 시 **재고 복구**
- 관리자 메모

### 권장 처리 순서

**반품**
1. 고객 요청 → 2. **승인** → 3. 상품 수령 후 **회수·검수 완료** → 4. **처리 완료**(토스 환불 ON)

**교환**
1. 고객 요청(+희망 사이즈) → 2. **승인**(재고 hold) → 3. **회수·검수 완료** → 4. **처리 완료**  
   (환불 없음 · 사이즈 변경·재고 정리)

**환불만**
1. 고객 요청 → 2. (승인 선택) → 3. **처리 완료**(토스 환불)  
   ※ 회수·검수 버튼 없음

### CS 상태 의미
| 상태 | 의미 |
|------|------|
| 요청접수 | 고객 접수 |
| 승인 | Admin 수락 |
| 회수/검수완료 | 물품 확인 |
| 처리완료 | 환불·교환 완료 |
| 반려 | 거절 |

## 6) 권장 관리자 E2E 시나리오

### A. 상품 → 주문 → 배송 → CS (반품)
1. 상품 등록 (진열함·판매함·재고)  
2. 구매자(회원 또는 비회원) 결제 성공 확인  
3. 배송준비중 → 배송중(송장) → 배송완료  
4. 구매자가 CS 반품 요청  
5. 승인 → 회수·검수 → 처리 완료(토스 환불·재고복구)  
6. 주문 상태·환불액·재고 확인  

### B. 교환
1. ~배송완료까지 동일  
2. 고객 교환 요청  
3. 승인(hold) → 검수 → 처리 완료  
4. 주문 상품 사이즈·재고 hold/완료 로그 확인  

### C. 품절·재입고
1. 재고를 0으로 조정 → 공개 목록에서 사라지는지  
2. 재고 증가 → 다시 노출되는지  

### D. 판매안함
1. 판매안함 저장 → 상세에서 구매 불가 · 장바구니 결제 차단

## 8) 자주 하는 실수

| 증상 | 조치 |
|------|------|
| 고객이 CS 버튼을 못 봄 | 주문을 배송중/배송완료로 변경 |
| 교환 승인 실패 | 희망 사이즈 재고 부족 · hold SQL 실행 여부 |
| 처리 완료 시 토스 오류 | payment_key · 라이브/테스트 키 확인 |
| 상품이 안 팔림 | 진열함·판매함·재고>0 확인 |
| Admin 403 | 계정 role=admin 확인 |
